# session-inbox

自分（親）はこの Mac の Claude Code。子は別の Mac で動く Claude Code のセッションで、ハブ（`~/.config/session-inbox/config.json` の `hub`）を通して `inbox` コマンドで扱う。材料はそのまま渡されるので、読んで判断するのは親の仕事。

## 既定の使い方（頼まれなくても子を使う）

子を立てる判断は親が自分でする。本人が「子を立てて」と言うのを待たない。

- 依頼の中に、互いに独立した作業が2つ以上あれば、作業ごとに子を1体立てて同時に走らせる。自分は1体ずつ順にやらない。
- 1本の作業でも、この Mac の状態（開いているファイル、ブラウザ、本人との会話）に依らず、長くかかるものは子に出し、自分は次の判断に戻る。
- 子を使わないのは、本人とのやり取りの最中の短い作業、この Mac にしか無いものを触る作業、本人が「ここでやって」と言ったとき。
- 子の置き場は既定で `config.json` の `defaultMachine`（常時起動の Mac）。同時に走らせるのは5体まで。子ごとに別の作業ディレクトリ（別リポジトリか git worktree）にして、同じファイルを2人に触らせない。
- 手順は、`inbox spawn` を作業の数だけ、`inbox send` を全部出してから `inbox wait <対象>...` で全員を待つ。1体ずつ `run` で待たない。
- 立てた子と頼んだことは、本人に先に1行で伝える（「<マシン名> に子を3体立てて、A、B、C を頼んだ」）。終わったら結果をまとめ、子は `inbox stop` で消す。

## 仕組み

- 子はふつうの Claude Code。親の文は子の会話に「別のセッションからのメッセージ」として届き、1行目に `from agent:<マシン>/<親の sessionId 先頭8文字>/<役割> via <ハブのホスト名>` が付く。この行から、画面（一覧と会話の見出し）と `inbox show` の「親」が親子をたどる。子はそれを作業依頼として扱うが、本人の発言ではないので、設定・権限・公開の操作は本人の確認を求める。
- 子への文は1ターンに1件。子の返事は子の transcript から `inbox read` で読む。子から親へ送り返す道は無い。
- 子が `waiting`（権限プロンプトか質問で止まっている）のときは送らない。ふつうは保留されて解けたあとに届くが、送った文がプロンプトを中断して（待っていたツールを「No」にして）届いたことが3回中1回あった。本人に知らせる。
- 子に質問をさせない。文に判断の材料を全部入れ、「迷ったら自分で決めて、決めたことと理由を書け」と書く。子が AskUserQuestion を出すと `waiting`（`input needed`）で止まり、親には答えられない。

## 流れ

1. `inbox list` で全マシンのセッションを見る。止まっているマシンも出る。
2. 子が無ければ `inbox spawn <マシン> <dir>` で立てる。
3. `inbox show <対象>` で状況を読む。`status`、`permissionMode`、ブランチ、PR、Claude Code 自身の要約、最後のやり取り、保留中の割り込み。
4. 子が1体なら `inbox run <対象> "<文>" --as <自分の役割名> --wait 600` で送って返事を待つ。名乗る名前は CLI が `<このマシン名>/<自分の sessionId の先頭8文字>/<役割名>` に組み立てるので、`--as` は役割名だけ（例: lead、reviewer）。複数なら `inbox send` を全部出してから `inbox wait <対象>... --wait 600`。
5. 終了コードで分ける。0 は返事が出そろった。2 は時間切れで、`inbox read <対象> --wait 600` で続きを待つ。3 は本人の入力待ちで、本人に知らせる。4 は送った文が保留のままで、待つ。
6. 済んだら `inbox stop <マシン> <tmux名>` で子を消す。本人の指示で残す場合はそのまま。

## コマンド

```bash
inbox list                                     # 全マシンのセッション
inbox spawn <マシン> <dir> [--name <tmux名>]     # 子を立てる。tmux で claude --dangerously-skip-permissions。<マシン>/<名前> と sessionId を返す
inbox stop <マシン> <tmux名>                     # 子の tmux を消す（既定の tmux 名は child-<dir の末尾>）
inbox show <対象>                               # 1つのセッションの状況
inbox send <対象> "<文>" [--as <名前>]           # 文を送る。応答の offset を覚える
inbox read <対象> [--wait <秒>] [--all]         # 最後に送った文への返事を読む（既定 120 秒まで待つ）
inbox run <対象> "<文>" [--wait <秒>]           # send のあと read（子が1体のとき）
inbox wait <対象>... [--wait <秒>]              # 送ってある複数の子を同時に待つ。子ごとに返事と状態を出し、終了コードはいちばん大きいもの（既定 600 秒）
inbox read <対象> --since <offset>              # 送っていなくても、その offset 以降を読む
inbox show <sessionId> --machine <マシン>        # 終了して一覧に無いセッションを読む
```

`<対象>` は sessionId、その先頭 8 文字以上、`<マシン>/<名前>`、`<名前>` のどれか。名前が2台にあると候補を出して止まる。`<文>` を `-` にすると標準入力から読む。`--as` は役割名だけで、使えない文字は `-` になる。

`spawn` は `ssh <マシン>` で tmux を立てる（ssh のホスト名はマシン名と同じ）。初めてのディレクトリは Claude Code の信頼確認が出るので自動で答える。一覧に出るまで最大 40 秒待つ。この Mac なら ssh を使わない。

どの場合も `read` と `run` の最後に `status`、`waitingFor`、`permissionMode`、`offset` が生のまま出る。終了判定に頼らず自分で見る。

## 命令の書き方

- 1通で自己完結させる。目的、作業ディレクトリ、完了条件、やってはいけないこと、最後に「結果を文で書いて」。
- 長い作業の途中は `inbox show` の「Claude の最後の発言」と「直近のツール操作」で見る。催促の文は送らない。子のターンが乱れる。
- 複数の子に同じ前提を伝えるときも、文は子ごとに書く。他の子が何をしているかと、触ってはいけない範囲を入れる。

## 触らないもの

- 自分が立てていないセッション。本人が指定したときだけ送る。一覧には SDK や他のツールが立てたセッションも出ることがある。
- この Mac で本人が使っている対話セッション。自分（親）も一覧に出るが、自分には送らない。

## 本人への報告

子ごとに、何を頼み、何が返り、何が残っているかを文でまとめる。子の返事をそのまま貼らない。

## 状況の読み方

- `status` が `waiting` なら止まっている。`waitingFor` が `permission prompt` なら権限プロンプト、`input needed` なら質問（AskUserQuestion）。
- `permissionMode` が `default` でも、子が idle なら文は承認なしで届く（確認済み）。保留されるのはプロンプトで止まっているときで、`show` の「保留中の割り込み」と `read` の終了コード 4 で分かる。
- 欠けている項目は「不明」。古い Claude Code のノードでは `permissionMode` が不明になることがある。

## 設定

- `~/.config/session-inbox/parent-token.json` に `{"client_id","client_secret"}`（Access のサービストークン、0600）。
- `~/.config/session-inbox/config.json` に `{"hub":"https://<ハブ>","defaultMachine":"<マシン名>"}`。
- `--hub http://127.0.0.1:<port>` で手元のノードに直接向けられる。試験専用で、送り主は `via localhost` になる。設定のハブでも手元でもないホストにはトークンを付けずに断る。
